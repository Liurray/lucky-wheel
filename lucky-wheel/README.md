# 全服幸運輪盤（動態登記人數共享獎池）

多人即時同步抽獎網頁。每位參加者可自行進入同一活動代碼並抽獎一次；主輪盤分數累積至共享獎池，抽完主輪盤後有 15% 機率觸發特殊輪盤。

## 活動規則

- 人數：依同一活動代碼內成功登記的暱稱數計算，不設 80 人上限；每位登記者限抽一次
- 主輪盤分數機率：60（15%）、300（25%）、980（25%）、1,980（20%）、3,280（12%）、6,480（3%）
- 特殊事件觸發機率：15%
- 特殊輪盤：解鎖 +1 顆虛寶（40%）、+500 分（30%）、+1,000 分（20%）、+2,000 分（10%）
- 初始虛寶 3 顆，上限 6 顆；已達上限再抽中解鎖時改為獎池 +500 分
- 獎勵級距：以 80 人的 80,000 / 110,000 / 140,000 分為基準，依當前登記人數 / 80 等比例調整（向上取整）；若有人繼續登記，門檻會即時變動
- 預算上限 100,000 元；虛寶每顆以 5,000 元計，紫色籤子每人以 690 元計。畫面會依實際登記人數顯示預算估算與可負擔級距。

## 本機啟動

```bash
npm install
npm start
```

開啟 `http://localhost:3000`，輸入活動代碼及暱稱即可加入。同一活動代碼下的參加者共用獎池。把相同網址及活動代碼分享給參加者；參加者輸入自己的暱稱後可自行抽獎。

## 部署

可部署至支援 Node.js 18+ 的服務。Build command：`npm install`；Start command：`npm start`。需要支援 WebSocket。請確認部署平台的檔案系統可持久化，因為目前活動資料保存在專案目錄 `data.json`；若平台使用 ephemeral filesystem，重新部署或重啟可能遺失資料。

## 注意

這是輕量活動原型，資料持久化採 JSON 檔，適合測試與小型活動。正式重要活動建議改用 PostgreSQL/Supabase、加上管理員驗證、備份與完整稽核。活動代碼不是管理員密碼，請勿將此原型視為具備正式身分驗證的金融或高風險抽獎平台。

## 動態登記人數注意事項

登記人數為房間內已登記的不同暱稱數（包含離線者），不是當前線上人數。新成員加入後，門檻及預算估算即時重算。所有已登記者都抽完後，若仍有新成員登記，進度會再次變成未完成；正式結算前建議主持人先停止分享入房資訊並確認登記名單。按人數等比例調整只能近似維持 80 人時的達標機率，不保證精確一致；固定 10 萬元預算也可能使高級獎勵被降級。

## 房間名單與輪流抽獎
- 每位玩家以活動代碼與 ID 登記，房間主畫面依登記先後顯示所有玩家及上線狀態。
- 系統依登記順序輪流抽獎，只有目前輪到的 ID 的「開始抽獎」按鈕可用；伺服器亦會拒絕其他玩家提前抽獎。
- 特殊事件及隱藏輪盤全部完成後才輪到下一位；離線玩家保留位置，需回線操作。新加入者排在隊尾。
- 同一瀏覽器會保留 ID 驗證 token，避免其他瀏覽器搶用已登記 ID；請勿清除瀏覽器 localStorage。


### 10 秒輪盤及二次確認（本版）
- 主輪盤、特殊輪盤均為 10 秒，約前 2 秒加速、5.5 秒高速、最後 2.5 秒減速。
- 特殊事件先由當前玩家按「揭曉福運」開啟隱藏輪盤浮窗，再按「開始特殊輪盤」才旋轉。
- 伺服器驗證只有本回合玩家可按；兩個階段均保留 45 秒超時自動繼續。


## 主持人邀請碼與踢人
啟動前在伺服器設定 `HOST_INVITE_CODE` 環境變數，例如 Linux/macOS：
`HOST_INVITE_CODE='請自行設定一組強密碼' npm start`
Windows PowerShell：`$env:HOST_INVITE_CODE='請自行設定一組強密碼'; npm start`
進房後輸入邀請碼，驗證成功才會顯示每個玩家旁邊的 × 移除按鈕。邀請碼只在伺服器比對。被移除的瀏覽器識別碼不可重新登記，直到管理員清除 data.json 中的 banned 清單。抽獎中的玩家需等結算後才可踢除；已結算的分數不會因踢人回溯扣除。輪盤動畫統一 6 秒。


## 進房主持人模式（本版）
進房畫面三個欄位：活動代碼、玩家 ID、主持人邀請碼（選填）。留空為一般玩家；輸入 `L4ACGQE7F` 為主持人，直接取得玩家名單旁的踢人權限。錯誤邀請碼會拒絕進房。邀請碼由伺服器驗證，不放在前端程式；部署時可用 `HOST_INVITE_CODE` 環境變數覆蓋預設碼。請注意預設碼已公開於本活動規格，正式公開部署建議使用環境變數改為私人碼。


## BOSS 扣血與獎勵階段
主畫面以最高門檻為 BOSS 初始 HP。每次玩家點擊「知道了」完成結算，伺服器廣播 drawComplete，所有客戶端播放傷害數字，並根據 state.pool 將 HP 減少至 max(0, thresholds.card990 - pool)。所有獎勵里程碑位於血條下方。主輪盤只有六種紋玉分數；15% 特殊事件由伺服器獨立判定，不會成為主輪盤格子。

請注意：最高門檻達成不保證最高面額可支付，最終實際獎勵仍受 NT$100,000 預算上限限制。

## 動態輪盤傷害（新版）

- 主輪盤六格的抽中權重不變（15%、25%、25%、20%、12%、3%），但每格的「實際傷害」會依房間登記人數計算，所有玩家看到相同的動態數值。
- 基準傷害係數為 0.80，超過 80 人後，再乘以 `(80 / 人數) ^ 0.25`。結果四捨五入至 10 分，最低 10 分。
- 例如 80 人房間六格為 50、240、780、1,580、2,620、5,180 傷害；人數更多時會略微降低。
- 啟動前可設定 `DAMAGE_FACTOR=0.75` 以調低傷害（允許 0.30～1.00）。
- 特殊事件仍是主輪盤結束後獨立 15% 觸發，不會佔用主輪盤格子。
- 達標機率會受抽獎隨機性、特殊事件、房間增減人數影響；此係數是保守控速，不是精確的機率校準。
- 已抽玩家的傷害以當時抽獎時的登記人數固定，不會追溯改動。
